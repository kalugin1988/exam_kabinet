# Единый кабинет экзаменов

Импорт таблиц, управление учреждениями и кабинетами, рассадка участников и
печатные документы работают в одном приложении. Основной проект находится в
`exam_kabinet`. Репозитории `exam_parser` и `exam_print` сохранены как исходные
версии; запускать их для работы единого приложения не требуется.

## Запуск

Нужен **Node.js 24 или новее**. В подготовленной облачной среде зависимости уже
установлены. Из директории `exam_kabinet` запустите:

```sh
npm start
```

При первом развёртывании установите зависимости по lock-файлу командой `npm ci`.
Приложение использует чистый JavaScript, Express, EJS и встроенный `node:sqlite`.
Отдельный сервер базы данных не требуется. По умолчанию используется порт 3000;
его можно изменить через `PORT` в `.env`.

## Первый вход и администратор

Перед запуском можно создать `.env` на основе `.env.example` и задать:

| Переменная | Назначение |
| --- | --- |
| `ADMIN_LOGIN` | Логин администратора, от 1 до 128 символов |
| `ADMIN_PASSWORD` | Пароль администратора, от 12 до 1024 символов |
| `JWT_SECRET` | Случайный секрет JWT, не менее 32 байт |
| `PORT` | Порт HTTP-сервера |
| `COOKIE_SECURE` | `true` для доступа через HTTPS |

Не заданные при первом запуске значения генерируются криптографически и
сохраняются в SQLite. Если пароль сгенерирован, логин и начальный пароль доступны
в `data/initial-admin.json`, доступном только владельцу файла. Существующий файл
не перезаписывается: при необходимости создаётся `initial-admin-<UUID>.json`.
Пароли и секреты не выводятся в журнал и не передаются через публичные API.
Если запись администратора уже существует, но её логин, хеш пароля или секрет
отсутствуют либо имеют непригодный формат, запуск восстанавливает только
недостающие поля. Существующие файлы начальных учётных данных сохраняются.

При **каждом `npm start`** приложение сверяет указанные значения из `.env` с
базой и обновляет администратора. `.env` имеет приоритет над одноимёнными
переменными процесса; незаданные поля сохраняют значения в базе. Изменение
логина, пароля или секрета завершает прежние сессии. В процессе работы
проверка пароля и JWT используют запись администратора из базы.

Пароль хранится в виде хеша `scrypt` с индивидуальной солью. JWT имеет срок
8 часов и хранится в HttpOnly-cookie с `SameSite=Strict`; токен не сохраняется
в `localStorage`. Сервер проверяет алгоритм, издателя, аудиторию, роль,
версию администратора и активную сессию. Выход отзывает токен в базе.
Защищённые API также поддерживают заголовок `Authorization: Bearer <токен>`.
На HTTPS установите `COOKIE_SECURE=true`; в production cookie всегда Secure.

## Рабочий сценарий

1. Войдите в систему и откройте «Импорт данных».
2. Загрузите XLSX, XLS или CSV со сканами, участниками либо учреждениями.
   Максимальный размер файла — 20 МБ. Для CSV поддерживаются UTF-8, UTF-16 и
   Windows-1251. Предварительный просмотр показывает данные до переноса в рассадку.
3. В таблице участников выберите «Перенести в рассадку»; при необходимости
   укажите предмет. Повторный перенос обновляет данные участника и сохраняет его
   идентификатор и назначенное место. Неоднозначные записи показываются отдельно.
4. Создайте кабинеты: число парт, от 1 до 6 рядов и этаж.
5. В «Рассадке» выберите предмет и сформируйте места. Доступны ручное назначение,
   блокировка мест и обмен партами. Правила соседства проверяет сервер.
6. В «Документах» выберите предмет, дату, площадку и кабинет. Доступны ведомость,
   сводная ведомость, акт передачи, сопроводительный лист и список регистрации,
   включая документы сразу для всех кабинетов. Дополнительно сохранены формы Р/М
   с группировкой по кабинетам и школам, печатью и экспортом Excel.

Назначения относятся к конкретному предмету: разные экзамены могут использовать
одни и те же места. Переименование кабинета обновляет номера у его учеников.
При уменьшении кабинета ученики с исчезнувших мест становятся неразмещёнными.
Удаление кабинета сохраняет учеников и снимает их назначение в этот кабинет.
Повторный расчёт заменяет назначения выбранного предмета атомарно.

## Хранение и сохранность данных

Приложение создаёт `./data/` с `recursive: true` при запуске. Путь привязан к
директории приложения и не зависит от текущей директории оболочки.

| Путь | Содержимое |
| --- | --- |
| `data/exam.sqlite` | Все таблицы приложения, администратор и сессии |
| `data/exam.sqlite-wal`, `data/exam.sqlite-shm` | Служебные файлы SQLite WAL |
| `data/uploads/` | Временные загруженные таблицы до завершения обработки |
| `data/exports/` | Временные JSON-файлы экспорта для скачивания |
| `data/test-runs/` | Изолированные данные и артефакты тестов |

Скриптов очистки или удаления `data/` нет. После обработки удаляется только
конкретный временный файл загрузки или завершённого скачивания; база сохраняется.
Ошибки импорта откатывают транзакцию. JSON-восстановление проверяет все записи
перед заменой списка учеников; кабинеты должны существовать заранее.
Запросы с некорректными данными не изменяют список учеников.

`data/`, `.env` и зависимости исключены из Git. Для полной резервной копии
остановите приложение и сохраните весь каталог `data/`, включая файлы SQLite.
Экспорт JSON в интерфейсе сохраняет рассадку и сведения о размещённых участниках;
он не заменяет полную резервную копию. Старая внешняя PostgreSQL автоматически
не переносится и не удаляется. Для переноса доступны прежний JSON-экспорт
рассадки и повторная загрузка исходных Excel/CSV.

## Проверки

```sh
npm test
```

Тесты используют нативный Node.js runner и запускают приложение через `npm start`
в отдельных копиях внутри `data/test-runs/`. Рабочая база не изменяется,
тестовые каталоги не удаляются. Проверяются JWT, ошибки авторизации, синхронизация
`.env`, все типы импорта, рассадка, обмен партами, печатные формы, CRUD кабинетов,
транзакции и сохранение данных после перезапуска.
Набор содержит 19 проверок, включая корректные 401 у API без заголовка `Accept`,
восстановление отсутствующих полей администратора и обработку ошибок запуска.

`GET /health` публично сообщает только готовность HTTP-сервера.
`GET /api/health` проверяет базу и требует авторизации. Другие API и страницы
приложения защищены JWT; публичны вход и статические ресурсы. API возвращают
400/401/403/404/409/413/415/422/429/500 в зависимости от ошибки; сообщения
не содержат стеков и SQL. Интерфейс перенаправляет на вход при истечении сессии.
Недействительный токен, отсутствие входа и истечение сессии показываются
раздельными понятными сообщениями. Браузерная проверка Chromium прошла на
экранах 320, 390, 768, 1024 и 1280 px: проверены семантическая разметка,
переполнение страницы, авторизация, импорт, рассадка и печатные документы.

Excel-зависимость закреплена как `xlsx: npm:@e965/xlsx@0.20.3`: это публикация
SheetJS CE в npm сторонним издателем. Она сохраняет совместимость API и содержит
исправления известных проблем прежней версии 0.18.5. Подпись npm-пакета и SHA-512
архива проверены; точная версия и integrity записаны в `package-lock.json`.
